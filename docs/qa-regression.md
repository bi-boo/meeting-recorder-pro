# 会议录音 Pro 回归测试流程

本流程是项目质量门禁。以后任何代码、配置、打包脚本、权限、文档中涉及功能承诺的改动，在提交或发包前都要跑一遍，并记录结果。

## 执行原则

- 以打包产物为准测试，不只测试 Xcode Debug 版本。
- 每轮测试都要先退出旧版本，避免菜单栏旧进程响应快捷键。
- 测试录音必须放入临时目录或测试专用目录，结束后移走或删除，不污染真实会议录音。
- 修改用户偏好前必须备份，测试后恢复。当前应用可能读取沙盒容器偏好：
  `~/Library/Containers/com.meetingrecorderpro.app/Data/Library/Preferences/com.meetingrecorderpro.app.plist`
- 所有失败项必须记录失败原因、日志片段和是否阻塞发包。不能用“手感正常”代替证据。

## 零、一键自动化优先执行

以后任何实质性代码、配置、打包脚本或功能承诺改动，先跑自动化流程：

```bash
scripts/run_full_qa.sh
```

脚本会完成以下动作：

- 生成本轮 `qa-runs/YYYYMMDD-HHMMSS/` 目录。
- 执行 `./build_dmg.sh`，以 Release 打包产物为准测试。
- 通过 `--qa-scenario` 启动 App 内置 QA runner。
- 自动覆盖设置回读、麦克风录音、暂停继续、连续录音、系统声音、混合音源和定时自动录音。
- 运行 `scripts/qa_artifact_check.sh` 校验 DMG、签名、录音文件和最近日志。
- 输出 `qa-result.json`、`report.md`、构建日志、应用 stdout/stderr 和包校验日志。

可选环境变量：

```bash
QA_RECORD_SECONDS=8 QA_TIMEOUT_SECONDS=240 scripts/run_full_qa.sh
QA_INCLUDE_SYSTEM_AUDIO=false QA_INCLUDE_MIXED_AUDIO=false scripts/run_full_qa.sh
```

系统声音和混合音源依赖“屏幕录制”权限；未授权时自动化会触发权限申请，并在报告中标记为 `skipped`。授权后重新运行脚本即可补齐。

自动化预计覆盖 80-90% 的功能路径。以下场景仍需按本文件人工补测：菜单栏视觉状态、设置窗口 Tab、快捷键改绑与冲突、提醒弹窗点击、开机登录项、Finder 打开、录音中退出、强杀恢复、设备插拔、睡眠断言和系统权限撤销类异常。

## 一、构建与包体验证

1. 检查工作区状态：

   ```bash
   git status --short --branch
   ```

2. Debug 构建：

   ```bash
   xcodebuild -project SimpleRecorder.xcodeproj \
     -scheme SimpleRecorder \
     -configuration Debug \
     -derivedDataPath build/ReviewDerivedData \
     CODE_SIGNING_ALLOWED=NO build
   ```

3. 静态分析：

   ```bash
   xcodebuild -project SimpleRecorder.xcodeproj \
     -scheme SimpleRecorder \
     -configuration Debug \
     -derivedDataPath build/ReviewDerivedData \
     CODE_SIGNING_ALLOWED=NO analyze
   ```

4. 测试入口检查：

   ```bash
   xcodebuild -project SimpleRecorder.xcodeproj \
     -scheme SimpleRecorder \
     -configuration Debug \
     -derivedDataPath build/ReviewDerivedData \
     CODE_SIGNING_ALLOWED=NO test
   ```

   当前 scheme 已配置 `SimpleRecorderTests`，此命令必须通过；新增纯逻辑或可隔离边界逻辑时优先补充 XCTest。

5. 生成安装包：

   ```bash
   ./build_dmg.sh
   ```

   正式对外发布必须使用严格模式：

   ```bash
   RELEASE=1 ./build_dmg.sh
   ```

6. 校验 DMG、签名和录音样本：

   ```bash
   scripts/qa_artifact_check.sh \
     --dmg MeetingRecorderPro_YYYYMMDD.dmg \
     --app build/Release/SimpleRecorder.app \
     --recordings /path/to/test-recordings
   ```

   `spctl` 若提示 `Unnotarized Developer ID`，表示未公证。本地功能测试可以继续，对外分发前必须完成 notarization。`RELEASE=1` 会把未公证、stapler 校验失败或 Gatekeeper 不通过视为构建失败。

   `scripts/run_full_qa.sh` 默认要求 MP3、系统音频、混合录音和定时自动录音等核心场景不能被跳过；仅本机权限不完整的烟测可临时使用 `QA_ALLOW_SKIPS=true`。

## 二、启动与权限

| 编号 | 测试项 | 操作 | 通过标准 |
|---|---|---|---|
| 2.1 | 旧进程清理 | 退出或杀掉所有 `SimpleRecorder` 进程，再从 DMG 或 Release app 启动 | 只有当前测试版本在运行 |
| 2.2 | 菜单栏启动 | 启动应用 | 菜单栏出现图标，无 Dock 图标，无崩溃 |
| 2.3 | 麦克风权限 | 首次或已授权环境启动麦克风录音 | 未授权时出现系统权限请求；已授权时录音可直接开始 |
| 2.4 | 系统声音权限 | 切到“仅系统声音”或“麦克风 + 系统声音” | 只在选择系统音频相关来源时触发屏幕录制权限 |
| 2.5 | 日志初始化 | 查看 `~/Library/Application Support/Logs/MeetingRecorderPro_YYYY-MM-DD.log` | 启动、权限、设备、快捷键注册均有日志，无 `ERROR` / `CRITICAL` |

## 四、录音功能矩阵

每个模式都要生成真实文件，并用 `afinfo` 检查格式、时长、音频帧数。必要时用 `say` 播放系统语音制造可检测音频。

| 编号 | 模式 | 操作 | 通过标准 |
|---|---|---|---|
| 4.1 | 仅麦克风 | 开始录音 8-15 秒后结束 | 生成 `.m4a`；48kHz；单声道；时长大于 5 秒；日志 `丢帧: 0` 或无异常丢帧 |
| 4.2 | 仅麦克风暂停恢复 | 录音、暂停、等待、继续、结束 | 文件可播放；日志有暂停/继续；未出现写入失败 |
| 4.3 | 仅系统声音 | 切到“仅系统声音”，播放 `say 'system audio test'`，录 8-15 秒 | 生成文件可播放；日志音源为“仅系统声音”；没有 `SCStream` 错误 |
| 4.4 | 麦克风 + 系统声音 | 同时说话并播放 `say 'mixed audio test'` | 生成文件可播放；日志音源为“麦克风 + 系统声音”；无系统音频缓冲异常 |
| 4.5 | 连续两段录音 | 连续开始/结束两次 | 两个文件都保存成功，文件名不冲突 |
| 4.6 | 录音中退出 | 录音中选择退出并确认保存 | 应用退出前保存文件；下次启动没有卡在录音状态 |
| 4.7 | 强制退出恢复 | 测试目录录音中强制退出 app，再启动 | 已录内容可播放；应用能清理中断状态 |
| 4.8 | 最大时长设置 | 设置最小时长上限并开始录音 | 到达上限自动结束并保存。若不等待完整时长，必须记录未执行原因 |

## 六、定时计划全量检查

定时测试统一使用测试目录，测试前备份偏好，测试后删除临时计划并恢复偏好。

| 编号 | 测试项 | 操作 | 通过标准 |
|---|---|---|---|
| 6.1 | 新建单次计划 | 新建 1 分钟内触发的“不循环”计划 | 列表展示正确，触发后自动禁用 |
| 6.2 | 自动录音 | 新建 1 分钟内触发的“自动录音”计划 | 到点自动开始录音；弹出“录音已开始”；结束后文件保存 |
| 6.3 | 提前提醒 | 新建 1 分钟内触发的“提前提醒”计划 | 提前弹出“是否启动录音”；点击“开始录音”后开始录音 |
| 6.4 | 忽略提醒 | 提醒弹窗点击“忽略” | 不开始录音；任务按规则进入下一周期或禁用 |
| 6.5 | 每天循环 | 新建每天计划 | 下次触发时间计算正确，触发后顺延到下一天 |
| 6.6 | 每周循环 | 新建每周多选计划 | 周几展示、排序、下次触发正确 |
| 6.7 | 编辑计划 | 修改时间、循环、触发方式 | 保存后列表和下次触发时间刷新 |
| 6.8 | 删除计划 | 删除已有计划 | 计划从列表消失，重启后不恢复 |
| 6.9 | 启用/停用 | 关闭再开启计划 | 关闭后不触发，开启后重新计算下次触发 |
| 6.10 | 重复时间限制 | 创建相同时间计划 | 保存被拦截或给出冲突提示 |
| 6.11 | 数量上限 | 尝试创建第 7 个计划 | 被拦截或无法继续添加 |
| 6.12 | 有计划防休眠 | 开启“有定时计划时禁止系统睡眠”并保留启用计划 | `pmset -g assertions` 可看到应用相关防休眠断言 |
| 6.13 | 开机自动启动 | 开关“开机自动启动” | 系统登录项状态与开关一致；测试后恢复原状态 |

## 七、错误与边界场景

| 编号 | 测试项 | 操作 | 通过标准 |
|---|---|---|---|
| 7.1 | 目录不可写 | 将存储目录设为不可写测试目录 | 开始录音前被拦截，弹出目录权限提示 |
| 7.2 | 磁盘空间不足 | 在测试机或受控环境模拟可用空间不足 | 开始录音前被拦截，弹出磁盘空间提示 |
| 7.3 | 系统音频无权限 | 移除屏幕录制权限后选择系统声音录音 | 给出权限引导，不生成空文件 |
| 7.4 | 麦克风无权限 | 测试机重置麦克风权限后启动录音 | 给出权限申请或明确引导 |
| 7.5 | 设备变更 | 录音中插拔外接麦克风或耳机 | 自动保存并提示，或不中断且日志无错误 |
| 7.6 | 快速重复点击 | 连续快速触发开始/结束快捷键 | 防抖生效，不生成异常状态 |

## 八、收尾检查

1. 检查没有测试 app 残留：

   ```bash
   pgrep -fl SimpleRecorder || true
   ```

2. 检查没有 DMG 挂载残留：

   ```bash
   mount | rg '会议录音 Pro|meeting_recorder_qa' || true
   ```

3. 检查用户真实录音目录没有测试文件残留。
4. 恢复测试前偏好和登录项状态。
5. 查看最近日志：

   ```bash
   tail -n 240 "$HOME/Library/Application Support/Logs/MeetingRecorderPro_$(date +%Y-%m-%d).log" \
     | rg 'ERROR|CRITICAL|启动失败|写入失败|录音中断|录音已保存|丢帧'
   ```

6. 保存本轮 QA 记录，至少包含：
   - 测试日期和测试人
   - Git commit
   - DMG 路径和 SHA256
   - 测试机器和 macOS 版本
   - 每个编号的结果：通过、失败、未执行
   - 失败项日志片段和处理结论
