# 会议录音 Pro 稳定交付标准

本文件定义“什么时候可以停止继续排查，并进入交付”。它用于避免无限审查，也用于约束后续每次功能迭代。

## 交付分级

| 阶段 | 定义 | 必须满足 |
|---|---|---|
| 本机可用 | 开发机上可以稳定完成核心录音路径 | 单元测试、`./build_dmg.sh`、完整 QA 通过 |
| 小范围公开 beta | 可以发给少量用户试用 | 本机可用 + 人工冒烟测试通过 + 已知 P0/P1 为 0 |
| 正式公开分发 | 可以放到 GitHub Releases 或项目主页 | beta 标准 + `RELEASE=1 ./build_dmg.sh` 通过 + Gatekeeper accepted |

当前项目默认以“小范围公开 beta”为日常交付目标；正式公开分发必须额外完成 Developer ID 签名、公证和 Gatekeeper 校验。

## 问题级别

| 级别 | 定义 | 是否阻断 |
|---|---|---|
| P0 | 丢录音、录音文件损坏、应用无法启动、DMG 无法打开、隐私或凭证泄露 | 阻断 |
| P1 | 常用功能失败：麦克风、系统音频、混合录音、暂停继续、MP3、定时自动录音、录音中退出保存 | 阻断 |
| P2 | 低频边界或体验不一致：提示文案不准、设置状态不同步、人工授权场景不够顺 | 不默认阻断，但必须记录 |
| P3 | 样式、措辞、命名、轻微文档优化 | 不阻断 |

交付前 P0/P1 必须为 0。P2/P3 可以带着发布，但必须在 QA 报告或 changelog 中记录。

## 核心用户路径

以下路径全部通过，才算“录音软件本体稳定”：

1. 首次启动后能完成麦克风权限授权。
2. 麦克风录音能生成可播放 M4A。
3. 暂停/继续后文件可播放，时长不包含主要暂停时间。
4. 连续两段录音不会覆盖或丢文件。
5. MP3 输出能生成有效 `.mp3`，源 M4A 在成功转码后移除。
6. 仅系统声音和麦克风 + 系统声音能录到有效文件。
7. 定时自动录音能触发并保存文件。
8. 录音中退出应用时，退出前完成保存。
9. 录音期间防休眠断言生效。
10. DMG 中应用名、许可证、第三方声明齐全。

## 自动化门槛

每次实质改动后必须运行：

```bash
xcodebuild test -project SimpleRecorder.xcodeproj \
  -scheme SimpleRecorder \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath build/TestDerivedData
```

```bash
scripts/run_full_qa.sh
```

完整 QA 默认覆盖：

- 设置回读。
- 麦克风录音。
- 暂停继续。
- 连续录音。
- MP3 输出。
- 系统声音。
- 混合音源。
- 定时自动录音。
- DMG、签名、录音可解码/有效时长/非静音和日志校验。

核心场景被 skipped 时，默认视为失败。只有本机权限不完整的烟测可以临时使用 `QA_ALLOW_SKIPS=true`，但这种结果不能作为正式交付证据。

## 人工冒烟门槛

自动化通过后，以下项目至少在发布前人工测一次：

- 菜单栏图标、菜单项、开始/停止、暂停/继续。
- 设置窗口四个 Tab 的间距、切换、控件状态。
- 快捷键改绑和冲突提示。
- 录音中退出并确认保存。
- Finder 打开录音目录。
- 改保存目录后能写入。
- 开机自动启动开关与系统登录项一致。
- 长录音 30-60 分钟至少跑一次。

人工项不要求每次小改都全量执行；但影响录音、权限、设置、定时、打包时必须执行相关项。

## 发布包门槛

本机验证包：

```bash
./build_dmg.sh
```

通过标准：

- Release 构建成功。
- `.app` 和 `.dmg` codesign verify 通过。
- `hdiutil verify` 通过。
- DMG 根目录包含应用、项目许可证、第三方声明、PermissionFlow/Sparkle 完整许可证，以及 LAME 许可证、完整 `lame-3.100.tar.gz` 源码包和源码/重链接说明。

正式公开分发包：

```bash
RELEASE=1 ./build_dmg.sh
```

通过标准：

- Developer ID Application 签名。
- notarytool 通过。
- stapler staple 和 stapler validate 通过。
- Gatekeeper accepted。
- 正式发布消费的完整 QA 证据必须绑定当前 HEAD、版本和最终 DMG SHA-256；真实录音集成报告必须匹配当前 HEAD、版本和最终 Release App 可执行文件 SHA-256，DMG 内 App 必须是同一二进制。

## 代码质量门槛

代码达到以下状态即可交付，不追求“永远没有问题”：

- 录音生命周期只有一个明确状态机，不靠互相冲突的布尔值判断。
- 文件写入、停止、转码、退出的顺序清楚。
- 错误能进入日志，不能静默失败。
- 录音文件命名不会覆盖已有 M4A 或 MP3。
- 关键权限和系统能力不可用时，有提示或回退。
- 新增逻辑有对应测试或 QA 覆盖。
- 没有密钥、证书、同步冲突文件、构建产物进入 Git。

## 停止继续排查的条件

满足以下条件，就停止继续“再查一轮”：

- P0/P1 为 0。
- 最近一轮 `xcodebuild test` 通过。
- 最近一轮 `scripts/run_full_qa.sh` 通过。
- 相关人工冒烟项通过或明确记录为未执行。
- 文档和实际功能一致。
- Git 已提交，工作区没有未提交的相关改动。

后续只有在新增功能、修改高风险路径、升级系统依赖、收到真实用户反馈时，再重新进入完整排查。
