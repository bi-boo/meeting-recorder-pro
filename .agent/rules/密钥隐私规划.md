## 三、隐私保护规则

### 0. 项目初始化（必做）

#### 新项目必须创建 `.gitignore`
- 每次创建新项目时，**第一时间**在项目根目录创建 `.gitignore` 文件
- 必须包含以下基础排除规则：
  ```
  # 构建产物
  build/
  DerivedData/
  *.app
  *.dmg
  *.ipa
  
  # 敏感配置
  .env
  *.env
  api_keys.env
  *.pem
  *.p12
  *.mobileprovision
  
  # 系统文件
  .DS_Store
  ._*
  Thumbs.db
  ```

#### 用户提供密钥时必须创建 `.env`
- 当用户在对话中提供 **API Key**、**Secret**、**Token** 等敏感信息时：
  1. **立即创建** `.env` 文件存放这些密钥
  2. **确认** `.gitignore` 中已包含 `.env`（如未包含则添加）
  3. **创建** `.env.example` 模板文件，用占位符替代真实值
  4. **提醒用户**：密钥已安全存储，不会被提交到 Git

### 1. 路径脱敏
- 禁止在代码中使用硬编码的绝对路径（如 `/Users/xxx/...`）
- 必须使用相对路径、环境变量或系统 API 获取路径

### 2. 密钥管理
- API Key、Secret、Token 等敏感数据必须存放于 `.env` 文件或系统 Keychain 中
- 严禁硬编码任何密钥信息

### 3. 隔离配置
- 确保 `.gitignore` 包含所有敏感配置文件（如 `.env`, `api_keys.env`, `*.pem`）
- 敏感文件应尽早加入 `.gitignore`，避免意外提交

### 4. 历史检查
- 在准备上传 Git 前，主动检查 Git 历史记录是否曾包含敏感文件
- 如有敏感文件历史，使用 `git-filter-repo` 等工具清理

### 5. 模板化示例
- 发布包含敏感配置的项目时，必须提供对应的 `.example` 模板文件
- 例如：`api_keys.env` 对应 `api_keys.env.example`
