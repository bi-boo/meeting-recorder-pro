## 二、文档自更新规则

### 核心指令
1. **强制初始化**：在开始任务前，必须在项目根目录检查或创建 `docs` 文件夹，并在此文件夹内维护 `prd.md`（产品需求文档）、`architecture.md`（技术架构文档）和 `changelog.md`（修改记录）
2. **状态实时同步**：每当有代码变化时，必须同步更新 `docs/` 目录下的 `prd.md`、`architecture.md` 和 `changelog.md`
3. **决策前寻根**：在执行 `replace_file_content` 等修改指令前，必须先 `view_file` 读取一次 `docs/` 目录下的 `prd.md` 和 `architecture.md`，确保当前操作符合产品需求与架构设计

### prd.md 规范格式
要求 AI 维护以下结构的 Markdown 语义：
- `# [项目名称] - 产品需求文档`
- `## 目标与背景`：说明项目的起源、要解决的核心问题及预期价值
- `## 核心功能`：列出功能点及其简要描述
- `## 用户流程`：**核心动态部分**，使用清晰的一级 (H1)、二级 (H2)、三级 (H3) 标题来标明需求逻辑。后续增加或修改需求点时，必须根据此标题逻辑进行增删改
- `## 当前状态`：逐条记录每一次具体的修改记录或功能实现进展

> [!IMPORTANT]
> **需求层级管理**：PRD 的"用户流程"部分必须遵循 H1-H3 的标题层级。后续增加或修改需求点时，必须根据此标题逻辑进行增删改，确保逻辑严密且易于追踪。

### architecture.md 规范格式
要求 AI 维护以下结构的 Markdown 语义：
- `# [项目名称] - 技术架构文档`
- `## 系统架构概述`：整体设计说明及技术栈选择
- `## 模块说明`：核心模块、组件或服务的功能界定
- `## 数据模型`：关键实体的定义或核心数据流
- `## 关键决策`：记录架构设计中的重大决策及其考量
- `## 当前状态`：逐条记录架构变更或核心实现的修改记录

> [!IMPORTANT]
> **技术层级管理**：架构文档同样需遵循 H1-H3 的逻辑层级。技术实现的增减和变更必须严格匹配相应的层级标题，确保技术架构的可维护性。

### changelog.md 规范格式
要求 AI 维护以下结构的 Markdown 语义：
- # 修改记录
- 格式要求：
  - 使用 `# [YYYY-MM-DD HH:mm]` 作为每一条记录的标题
  - 必须包含以下四个列表项，确保回溯的精确性：
- 完整示例：
  ```markdown
  # [2026-01-14 01:20]
  - **用户需求/反馈**: (详细记录用户提出的原始需求或报错反馈)
  - **技术逻辑变更**: (说明修改了哪块的技术逻辑、框架调整或算法优化，无需贴具体代码)
  - **涉及文件清单**: 
      - `SimpleRecorder/Managers/AudioRecorderManager.swift`
      - `docs/prd.md`
  - **变更原因**: (补充说明此次修改的背景或必要性)
  ```
