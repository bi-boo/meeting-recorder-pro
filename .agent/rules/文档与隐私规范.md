# 文档与隐私规范

## 一、文档自更新规则

### 核心指令
1. **强制初始化**：在开始任务前，必须在项目根目录检查或创建 `docs` 文件夹，并在此文件夹内维护 `prd.md`（产品需求文档）、`architecture.md`（技术架构文档）和 `changelog.md`（修改记录）。
2. **状态实时同步**：每当有代码变化时，必须同步更新 `docs/` 目录下的 `prd.md`、`architecture.md` 和 `changelog.md`。
3. **决策前寻根**：在执行 `replace_file_content` 等修改指令前，必须先 `view_file` 读取一次 `docs/` 目录下的 `prd.md` 和 `architecture.md`，确保当前操作符合产品需求与架构设计。

### 文档规范格式
- **PRD**: 遵循 H1-H3 标题层级，重点维护“用户流程”。
- **Architecture**: 遵循 H1-H3 逻辑层级，记录关键决策和模块说明。
- **Changelog**: 使用 `# [YYYY-MM-DD HH:mm]` 标题，包含用户需求、技术变更、涉及文件清单和变更原因。

## 二、隐私保护规则

### 1. 路径脱敏
- 禁止在代码中使用硬编码的绝对路径（如 `/Users/xxx/...`）。
- 必须使用相对路径、环境变量或系统 API 获取路径。

### 2. 密钥管理
- API Key、Secret、Token 等敏感数据必须存放于 `.env` 文件或系统 Keychain 中。
- 严禁硬编码任何密钥信息。

### 3. 隔离配置
- 确保 `.gitignore` 包含所有敏感配置文件（如 `.env`, `api_keys.env`, `*.pem`）。
- 敏感文件应尽早加入 `.gitignore`，避免意外提交。

### 4. 历史检查
- 在准备上传 Git 前，主动检查 Git 历史记录是否曾包含敏感文件。
- 如有敏感文件历史，使用 `git-filter-repo` 等工具清理。

### 5. 模板化示例
- 发布包含敏感配置的项目时，必须提供对应的 `.example` 模板文件。
